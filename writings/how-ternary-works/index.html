2-bit Transformers, simply explained

By Eren Menges

I wrote this because all the explanations on the internet fried my mind when I was working on Avenue. This post is human-written, with AI only used to generate visuals/LaTeX equations from my handwriting, and provide mild guidance.

Prerequisites

Beginner knowledge of transformers, neural networks, and partial derivatives. Even a little intuition is enough.

What is the point?

Modern day Transformers have a problem: they are huge. They need to store a lot of parameters in memory, and modern day devices are mostly not compute, but capacity and bandwidth-bottlenecked at local LLM scale. If we had a way to store parameters using less space, we can run large models in small devices, or run small models faster!

What are ternary transformers?

Ternary transformers are regular transformers that have multiples of {-1,0,1} instead of [-inf, inf] as weights in their attention and MLP layers. Hence the name ternary.

Why not binary?

Why not {-1,1}? Because matrix multiplication is a dot product by nature. If we only had {-1,1}, we could only add or subtract signals, unable to ignore a signal.

Why not {0,1}? If we only used {0,1} weights, we could only add or ignore signals, unable to subtract a signal.

A lack of subtracting or ignoring signals would make the network less expressive and capable of representing the data, which is bad.

So how do they work?

Training

We actually don’t directly train the ternary weights {-1,0,1}. That would be kinda impossible. The issue would be flipping the weights. Since we only can have ternary values, we can only flip the weights in some way, not add to or subtract from them. You can’t push a weight from -1 to -0.98 because it results in lower loss, that’s just not permitted by the network.

So we can only flip them (e.g. -1 to 0 or 1). The issue here is the size of gradients. No gradient in a typical neural network is large enough to push a 1 to 0. Updates to weights are usually on the scale of 1e-3 to 1e-6. (footnote 4) Since we are only working with ternary values, adding or subtracting 0.001 to 1 is just going to be 1! Decimal values are not allowed in our network.

You might say, just scale up the gradients so they can push from 1 to -1! That idea wouldn’t work, because a gradient size of ~1 would overshoot in every step.

So how do we train the ternary weights? We don’t. We keep a full copy of the actual full-precision latent weights in the background and train them. What??!! This sounds stupid.

The math

Let’s define some stuff first: h means activations through the network, y means the output of the network, and L means loss function. Ω means weights, and Ω^ means weights that we quantized to ternary.

Back to the topic: It is actually not stupid, due to some math tricks. First of all, we TRAIN latent weights, which means we just change their parameters to satisfy a lower loss function.

Ωt+1​=Ωt​−lr⋅∇L

But we don’t use them for anything else. We do the forward pass with the ternary weights, and calculate the loss and gradients from that forward calculation with the ternary weights. For that, we use a quantizer.

ΩweightsΩ​ quantizer ​ quantizer ​ STE (later) ​​Ω^quantized weightsΩ^​ forward ​ forward ​ backprop ​​h, yactivations, logitsh, y​

So activations and logits are computed from the quantized ternary weights, while backprop still reaches the latent weights. Here is the trick:

The quantizer

As the quantizer, we use absmean scaling. If you’re confused, follow the examples below and you’ll get it. It’s all about scaling down the weight distribution to the [-1,1] number line.

We first take the absolute mean of the whole layer we are working on. Let’s call that abs_mu. We divide the whole layer by abs_mu, so we can get something like “How many average weights is this weight?” for each weight.

wabs_muabs_mu​=[0.2,−0.6,1.2,−0.1,0.4]=mean([∣0.2∣,∣−0.6∣,∣1.2∣,∣−0.1∣,∣0.4∣])=number_of_elements(w)sum(∣0.2∣,∣−0.6∣,∣1.2∣,∣−0.1∣,∣0.4∣)​=0.5​

scaled_down_weights​=abs_muw​=[0.50.2​,0.5−0.6​,0.51.2​,0.5−0.1​,0.50.4​]=[0.4,−1.2,2.4,−0.2,0.8]​

Then we clamp each weight to [-1,1]. So now any weight <= -1 is -1, and any weight >= 1 is 1. (footnote 1)

clamped_weights​=clamp(scaled_down_weights)=clamp([0.4,−1.2,2.4,−0.2,0.8])=[0.4,−1,1,−0.2,0.8]​

But we still are in floating point space, we have decimals and everything. So we round.

quantized_weights​=round(clamped_weights)=round([0.4,−1,1,−0.2,0.8])=[0,−1,1,0,1]​

So these are our weights now.

quantized_weights=[0,−1,1,0,1]

Scaling

Remember abs_mu? We don’t throw it out. This is because actually, we don’t convert weights to {-1,0,1}. Instead, for every layer, we have a scalar scale α. We multiply all the weights in a layer with α, so our weights are actually {−α, 0, α}. And when quantizing weights, that scalar α is our good old abs_mu. So we scale down the weights, clamp and round them so they are {-1,0,1}, and then multiply them by the same scale we used to scale them down, so they are back to their original scale.

quantized_weights_scaled_back_up​=abs_mu⋅quantized_weights=0.5⋅[0,−1,1,0,1]=[0,−0.5,0.5,0,0.5]​

Why do we even use scaled weights instead of pure ternary? Because pure ternary would only give us sparsity (which connections matter) but wouldn’t give us any kind of magnitude. The connections that survived (didn’t get zeroed) matter, and how much do they matter collectively? That’s what scale tells us

Clever mathematical trick making this all work: STE.

But how does backprop work on this? This is a regular backprop chain:

∂Ω1​∂L​=∂h3​∂L​⋅∂h2​∂h3​​⋅∂h1​∂h2​​⋅∂Ω1​∂h1​​

I call it a chain, because every layer passes their derivative and the activations’ derivative to their previous layer. However, we have an issue: the derivative of rounding is 0 almost everywhere.

If we put the quantizer in, it would look more like this:

∂Ω1​∂L​=∂h3​∂L​⋅∂h2​∂h3​​⋅∂h1​∂h2​​⋅∂Ω^1​∂h1​​⋅∂Ω1​∂Ω^1​​

Since the chain is all multiplication, inserting a zero there would zero every layer’s weight gradient and make updating weights impossible. That would be disastrous. But round also has a special feature:

What would be natural for round and also let gradients pass the quantizer without destroying them? Multiplying it with 1! We substitute the identity function here for the derivative of quantizer function.

∂Ω1​∂Ω^1​​=I

∂Ω1​∂L​=∂h3​∂L​⋅∂h2​∂h3​​⋅∂h1​∂h2​​⋅∂Ω^1​∂h1​​⋅I

Now the chain looks like our original backprop chain, with the only difference being omega hat at the end instead of omega. The chain consists of only differentiable functions’ derivatives. Since we compute the forward pass with quantized weights, every activation (h) in this equation came from our ternary weights. The backprop chain uses those activations to calculate the gradients, which is exactly what we wanted.

That is called a Straight Through Estimator (STE). With STE, the gradients flow without being destroyed. Also the identity function actually looks similar to the rounding function when we smooth it, which has a slope of 1. Beautiful.

This whole “train shadow latent weights" approach also solves our flipping problem. Imagine we are trying to push a weight 0 to 1. We can push it little by little (0.001) many times so it crosses the 0.50 boundary:

Example (after dividing by abs_mu):

0.480+0.001​0.481+0.001​0.482+0.001​⋯+0.001​0.499​0.501⇒Ω^:0→1

We couldn’t do that with training the ternary weights, because we can’t add small gradients to the ternary weights. It would do nothing!

What then?

So the latent weights get updated using STE. How do we train the next step? We just do this all again! Quantize latent weights and do the forward pass, calculate loss using that forward, backprop the quantized forward, and update latent weights. That’s pretty much it.

Why is inference fast?

Memory

Instead of storing the full decimals of every weight, we only store a {-1,0,1} per weight and a scaling scalar per layer. The information density of a ternary value is 1.58 bits (footnote 2), but computers can’t represent 1.58 bits. So we just store it in 2 bits: the sign bit, and the value bit.

ternary value 2 bits meaning
0 00 value bit zero
+1 01 value one, sign +
−1 11 value one, sign −
unused 10 unused

So we can pack four ternary values in one byte (8 bits)! In comparison, a classic FP16 weight needs 2 bytes (16 bits). Ternary = 2 bits. Full precision 16: 16 bits. We literally get an 8x density improvement.

Overall, that means much less bits to move in and out of memory, so a weight goes to the GPU from memory faster, and vice versa. It also means we can put more parameters in memory, so bigger models in memory-limited devices.

Compute

Remember how we said matrix multiplication is actually a dot product.

h⋅Ω=h1​Ω1​+h2​Ω2​+h3​Ω3​+⋯+hn​Ωn​

Well it involves products. And that’s expensive. But when we dot product with ternary values,

h⋅Ω^=(h1​⋅1)+(h2​⋅−1)+(h3​⋅0)+⋯+(hn​⋅1)=h1​−h2​+⋯+hn​

Example:

[3,5,2,7,4]⋅[0,−1,1,0,1]=(3⋅0)+(5⋅−1)+(2⋅1)+(7⋅0)+(4⋅1)

=−5+2+4=1

It’s just a collection of addition and subtraction and skips, which is way faster than products! (footnote 5)

Important part we deliberately skipped: activations.

We have been talking about weights only. But what happens to the input to the network, and the activations that follow that?

We quantize them too. Not to ternary though. We usually quantize them to a coarser but still somewhat precise integer format like int8 ([-128,127]).

You might ask, why don’t we quantize them to ternary? During training, weights get so many steps and chances to adjust to the quantization and still make the network work. But we can’t do it with activations, because there are no latent activations. An activation is not a parameter, it’s just a result of the input. An activation gets one chance, it’s quantized and done. It can’t adjust to being quantized like how weights do.

But wouldn’t ternary quantizing the weights be harmful too then? Not really. Through the layers, a weight coefficient being wrong usually averages out in the dot products, since errors are small and mostly random.

But the same can’t be said for activations. Activations are the only things that are being passed forward through layers, and even a small loss in quality (error) caused by ternary quantization might make that error compound as it goes through layers. The weights’ errors get averaged out, but if the activations are erroneous, there’s nothing that averages them out, and the signal that gets passed between layers becomes crap.

This is complicated, so I asked Claude for a metaphor for this: Imagine each layer is an election that uses the previous layer’s results to make up voters’ minds. Miscounting a few votes in random directions inside every election is fine, since the randomness makes the errors average out and the result stays truthful. But passing the wrong results to the next election? That’s disastrous.

Why don’t we leave them in full precision? Remember how dot product with ternary values is an addition/subtraction? Well not every addition is cheap. Floating point additions are more expensive than simple integer additions, so we like to make the activations integer to squeeze out the extra compute benefit. And activations cost memory too, so using less memory for each activation gives us some bandwidth/capacity benefit.

Why can’t we quantize the network after training it normally?

We can. It’s just going to suck. Here’s the results from my hobby experiment Avenue:

When we train it regularly, the network doesn’t learn to work with ternary quantized values. So the addition of this new quantizer into the layers just hurts the inner workings of the network. (footnote 3)

Why the hell does this work?

I don’t know. But it does. Research (further reading 1) shows in ~3B sizes ternary transformers match the performance of regular transformers the same size. That’s crazy.

Footnotes

  1. In the quantizer I swapped the order of rounding and clamping, because it’s more intuitive and mathematically equivalent.
  2. It’s actually not two bits. You can’t represent {-1,0,1} with just one bit, it’s just a simplification. In information theory, you can represent 2 options with 1 bit, and 4 options with 2 bits. It follows that 2^n = number of options. We have to solve 2^n = 3, which comes to ~1.58.
  3. Post-training quantization (PTQ) usually works when you quantize the weights to smaller but still precise numbers, e.g. FP16 to FP8. The network suffers a slight dip in quality, but it’s usually not bad. But especially for ternary quantizations, PTQ just destroys the network.
  4. Update to the weight = (gradient * learning rate)
  5. Multiplications on GPUs take roughly equivalent time. But they take way longer on CPUs, so ternary transformers make CPU inference much faster, even just accounting for the compute gains.
